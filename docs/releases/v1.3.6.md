# v1.3.6 release notes

Status: draft; the release has not been published.

This patch release corrects numeric bounds checks and comparison ordering. The fixes are included in [PR #1](https://github.com/cybergarage/go-safecast/pull/1).

## Fixes

- `ToUint8()` rejects `int16` and `int32` values above 255, and `ToUint16()` rejects `int32` values above 65535. Previously, these paths could wrap the value and return success. Pointer inputs and generic `To()` calls use the corrected checks.
- `FromFloat64()` rejects `2^63` when converting to `int64` and `2^64` when converting to `uint64`, as well as the corresponding native `int` and `uint` limits on 64-bit targets. These values previously passed checks because converting the integer maxima to `float64` rounded them upward. `FromFloat32()` and generic `From()` share the correction.
- `Compare()` now reverses the sign of a successful comparison made with swapped operands. For example, `Compare(int8(100), int16(256))` returns a negative result instead of a positive result.

## Tests and tooling

Regression tests cover the affected typed inputs, pointer and generic entry points, boundary neighbors, valid conversions, and comparison ordering in both directions. Additional conversion and equality tests, GitHub Actions updates, and golangci-lint configuration changes are included since v1.3.5.

## Compatibility

Public function signatures are unchanged. Applications that relied on overflowing conversions returning success will now receive errors from the affected paths. Applications that relied on the incorrect fallback ordering will receive the corrected comparison result.

Existing fractional truncation and nonfinite-value policies are unchanged. This release does not establish 32-bit build support; the existing `ToUint32()` implementation contains a separate 32-bit compilation issue.
